\section{Overview}
\label{sec:overview}

We follow the program of \cref{fig:tworuns} through \tool, and then a second program
that shows why levels of evidence are needed.

\paragraph{Record.} A PMPI library, preloaded into the unchanged binary, writes one
record per MPI call on each rank, with the call's arguments and returned status. The run
we record is run~A: the wildcard receive $r_0$ of rank~0 took rank~1's send $s_1$, and
the receive $r_0'$ from rank~2 took $s_2$. Non-overtaking makes the observed matching
$\Mobs = \{r_0 \mapsto s_1, r_0' \mapsto s_2\}$ recoverable from the records: per
receiving rank and source, receives take that source's messages in order.

\paragraph{Stretto.} An alternative changes the message of one wildcard receive. By the
first non-overtaking rule, only the earliest unconsumed message from each source can be
next. So $r_0$ has one alternative per other sender with a pending message, here
$\Malt = \{r_0 \mapsto s_2\}$.

\paragraph{Check.} Is $\Malt$ possible, and possible for which programs? After $r_0$
takes $s_2$, rank~0's continuation is unknown. It may branch on the status, so the
analysis keeps only rank~0's events up to the completion of $r_0$ and nothing after it.
Other ranks keep their events unless they depend on something removed: a blocking send
whose receive is gone, a receive whose message is gone. This greatest set closed under
such rules is the \emph{horizon} $\Hpre$ (\cref{sec:horizon}). Here it is rank~0 up to
$r_0$, rank~2 entirely, and rank~1 up to its send. Over $\Hpre$, \tool builds a
graph with an issue and a completion node per operation and a match node per matched
pair. Its edges are program order, the dependencies of each match, and MPI's ordering
rules (\cref{fig:graph}a). The graph is acyclic, so a topological order is an execution.
Every program that issues the recorded calls when it receives the recorded statuses can
perform it (\cref{thm:sound}). If rank~2 sent only after hearing from rank~0, the new
match edge would close a cycle (\cref{fig:graph}b), and no execution could realise
$\Malt$.

\paragraph{Classify and profile.} At \Lone, the trace alone says that $r_0$ can take a
message of the same type and size from another sender. This is class \cls{1f}, harmless
unless the continuation depends on it. Assuming in addition that rank~0 continues with the
recorded calls (\LoneSP), an exhaustive exploration of the straight-line program shows
that the receive from rank~2 never completes (\cls{1d}, deadlock) and that $s_1$ is never
received (\cls{1c}, orphan). The prediction holds at every buffering threshold. Its
witness is a pin, \texttt{STRETTO\_PIN=0:0:2}: on rank~0, wildcard receive number~0
takes rank~2's message.

\paragraph{Replay.} A second PMPI library substitutes the source of each pinned receive or
probe: the alternative's sender at the changed receive, the recorded sender at every other
wildcard of the horizon. It logs the source each pinned operation matched. The finding is
confirmed when every pin matched, the run shows the predicted outcome (here a hang), and a
control run with the observed sender at the changed receive finishes.

\paragraph{Levels of evidence.} The single-path assumption that turned \cls{1f} into
\cls{1d} above is the restriction under which earlier MPI predictors state their
guarantees~\citep{forejt17mopper}, and no trace shows that a program meets it. A master that
receives a result from \anysrc and replies to \texttt{status.MPI\_SOURCE} breaks it: if its
first receive takes worker~2's result, the recorded calls still reply to worker~1 first, which
deadlocks under rendezvous, while the real master replies to worker~2 and finishes. If instead
the source shows that rank~0 of \cref{fig:tworuns} reads nothing of $r_0$'s result before its
second receive, the deadlock above holds for the program itself (\cref{sec:firstread}). \tool reports each
finding with its level: \Lone (trace only, sound for every consistent program), \LoneSP (adds
the single-path assumption) or \Ltwo (adds a skeleton of the calls that depend on message
metadata; \cref{sec:levels}).

\paragraph{Buffering.} Two ranks that each \mpicall{Send} 400 bytes to the other and then
\mpicall{Recv} finish on Open MPI's defaults and deadlock under rendezvous: the recorded run
is realisable only for $\Bt \ge 400$ (\cls{2-buffering}). Each prediction carries the set of
thresholds at which it holds (\cref{sec:buffering}).
