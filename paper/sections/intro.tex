\section{Introduction}
\label{sec:intro}

Large simulations run as thousands of processes that share no memory and communicate by
sending messages. Almost all of them use the Message Passing Interface
(MPI)~\citep{mpi50}. MPI programs are usually deterministic by construction: every
receive names the process it expects a message from. One feature breaks this. A receive
may pass the wildcard \anysrc and accept the first matching message from any sender. Work
pools use it to serve whichever worker finishes first. Solvers use it when the set of
neighbours is not known in advance (AMG), and reduction trees use it to collect partial
sums in arrival order (Nekbone). Source wildcards appear in 3 of 14 US exascale proxy
applications, and a tag wildcard in a fourth~\citep{sultana21proxy}.

\Cref{fig:tworuns} shows how little it takes for a wildcard to matter. Rank~0 receives
once from anyone and then once from rank~2. Ranks~1 and~2 each send one message. In
run~A, rank~1's message arrives first: the wildcard takes it, the second receive takes
rank~2's message, and the program finishes. In run~B, rank~2's message arrives first and
the wildcard takes it. The receive from rank~2 then waits forever, and rank~1's message
is never received. Both runs are legal MPI. Which one happens is decided by the network,
the load on the node and the MPI library's progress engine. The bad order may appear once
in thousands of test runs, disappear when the test is repeated under a debugger, and
then surface at scale. A race in a laser--plasma code appeared only at 524\,288 processes
and took months of debugging with print statements~\citep{laguna15cacm}. A message race
in the HYPRE solver library hung a production code intermittently for 18 months; diagnosing
it took 291 jobs and 10\,392 compute-node hours, and the fix was ten
lines~\citep{sato17ninja}. HYPRE's change log places the fix in its ParaSails
preconditioner~\citep{hypre-changelog}.

Existing tools cover this poorly. Runtime checkers such as \MUST~\citep{hilbrich12must}
watch the run that happened. When that run takes the good order, there is nothing for them to
report. Exhaustive verifiers such as ISP~\citep{vakkalanka08isp},
DAMPI~\citep{vo10dampi}, MPI-SV~\citep{yu20mpisv} and CIVL~\citep{siegel15civl}
enumerate the schedules of a program. They pay for every competing wildcard or give up
completeness. Predictive analyses take one trace. MPI-PRV~\citep{yao26mpiprv} predicts
violations of temporal properties soundly and without a solver, but it keeps every wildcard
match of the trace fixed and assumes zero buffering. Reachability
testing~\citep{tai97race,lei06reachability} changes matches: it derives the messages that
could have raced for each receive, asserts that the resulting variants are feasible, and runs
each one. Solver-based predictors~\citep{huang13ase,forejt17mopper,huang20ase,khanna18hermes}
search other matchings for deadlocks and assertion violations. Their guarantees hold for
single-path programs, whose calls do not depend on what, or from whom, they receive, or for
the branch conditions the run recorded. No trace certifies the first, and a destination
computed from a receive's status is no branch. On a master that replies to whoever sent the
last result, a single-path prediction reports a deadlock that no execution has.

Shared-memory concurrency has a theory of prediction from one trace. The maximal causal
model~\citep{serbanuta12mcm}, rooted in feasible program prefixes~\citep{netzer91accuracy},
considers every program that can produce the trace and stops a thread at its first read
whose value changes; RVPredict made it algorithmic~\citep{huang14rvpredict}. Later analyses
prove that a reordering is a run of every such program~\citep{smaragdakis12cp,mathur18shb},
and decide this in linear time for well-chosen classes of
reorderings~\citep{kini17wcp,mathur18shb,mathur21syncp,tunc23spd}. Their soundness now has a
common definition~\citep{liu25soundness}. The frame carries over to message passing, but
not verbatim. A reordering that keeps every read's writer becomes one that keeps every
match, which is what MPI-PRV predicts. Changing a match changes a read, with four
differences: a nonblocking receive's result is observed only at its completion call, long
after its match; a message is consumed, so the receive that took it in the trace loses it;
non-overtaking orders matches, not completions; and whether a send completes depends on the
buffering threshold of the MPI implementation.

\paragraph{This paper.} For MPI's matching semantics (wildcard source and tag over
non-overtaking queues, nonblocking requests whose match precedes their completion, probes,
completion order, collectives and a per-message eager threshold), we prove which
alternative matchings one trace certifies for every program consistent with it, up to the
part of the run the change leaves determined, the \emph{horizon}, and decide them in
quasi-linear time without a solver. Our tool \tool predicts such matchings, classifies their
consequences, and confirms them by replay. Everything in the horizon happens identically under
the alternative, and nothing after a changed receive is assumed. Inside it, an alternative is
feasible iff a constraint graph over issue, completion and match events is acyclic;
happens-before concurrency, with which earlier message-race tools select candidates, cannot
tell feasible from infeasible alternatives once a nonblocking wildcard is pending
(\cref{sec:graph}). Each prediction carries the buffering thresholds at which it holds, and
each finding its level of evidence: \Lone findings follow from the trace alone, \LoneSP
findings also assume the single-path continuation of earlier work, and \Ltwo findings use a
skeleton of the program's dependence on message metadata.

\paragraph{Contributions.}
\begin{itemize}[leftmargin=*]
\item For MPI's matching semantics, the first proof that an alternative matching is
  realisable by every program consistent with the trace up to the horizon (\cref{thm:sound}),
  with consistency as in the maximal causal model~\citep{serbanuta12mcm}, and a check by the
  acyclicity of a constraint graph with match nodes, complete relative to the horizon
  (\cref{thm:complete}).
\item Buffering profiles. Above the threshold the recorded run itself needs, feasibility of a
  steal at a blocking receive is monotone in the eager threshold (\cref{thm:mono}), so its
  thresholds form an interval found by bisection. Deadlock predictions are not monotone
  (\cref{prop:nonmono}), the formal counterpart of an observation on slack
  elasticity~\citep{vakkalanka10slack}.
\item Levels of evidence, a reporting discipline with shared-memory
  counterparts~\citep{kalhauge18sound,farzan12exceptionull}. Single-path predictions can be
  false on code whose control flow depends only on message metadata (\cref{lem:sp}).
  Deadlocks contained in the horizon after a changed match are predicted without that
  assumption (\cref{thm:l1dead}).
\item \tool: a PMPI tracer, an analyser whose check is quasi-linear in the trace per
  alternative (\cref{thm:cost}), and a replay library whose pins cover the horizon, whose log
  shows that each forced match happened, and whose confirmations need a control replay.
\item An evaluation on the MPI Bugs Initiative and \MBB against \MUST and against repeated
  randomised runs, a differential check of soundness against an exhaustive explorer, and
  real applications. On the MPI Bugs Initiative, \tool finds \nMBItpunion of the
  \nMBIerrors labelled errors with no false positive, against F1 \MBIfoneMUST for \MUST and
  \MBIfonestress for randomised runs, which never expose the \nMBIStressPredMissed buffering
  bugs \tool predicts.
  From single clean runs of HYPRE~2.10.1, \tool finds the ParaSails race as a probe
  alternative (\Lone) in \nHypreExposed of \nHypreTraced runs. All \nHypreCrossAlts pinned
  replays hang while their controls finish, and the fixed version has no such alternative.
  In NPB MG~2.4.1 it predicts the documented wildcard bug of the halo exchange: forced,
  \nMGChanged of \nMGReplayed replays compute another residual.
\end{itemize}
