\section{Evaluation}
\label{sec:eval}

\pending{Every number in this section is provisional (blue): it comes from the run before
the soundness and evidence fixes, and the tables are regenerated from the CSV files by
\texttt{experiments/tables.py} after the rerun.}

We ask six questions.
\begin{description}[leftmargin=*,style=nextline]
\item[RQ1, soundness in practice.] Does the check ever accept an alternative that no
  execution realises, and does every replayed finding behave as predicted?
\item[RQ2, effectiveness.] Which labelled bugs does \tool find from one run, compared
  with \MUST on the same programs and with repeated randomised runs?
\item[RQ3, buffering.] How many recorded runs and alternatives depend on the threshold,
  and do the predicted thresholds hold on a real implementation?
\item[RQ4, levels.] Where do \Lone, \LoneSP and \Ltwo disagree, and why?
\item[RQ5, cost.] What do tracing and analysis cost?
\item[RQ6, real applications.] What does \tool report on wildcard-heavy correct code, and
  what do its alternatives change?
\end{description}

\paragraph{Setup.} Programs are built with Open MPI~4.1.6 and MPICH~4.2 on Ubuntu~24.04
and run on one node. Corpora: the message-race, tag-matching, buffering and probe programs
of the MPI Bugs Initiative~\citep{laurent21mbi} (\nMBIprogs programs, \nMBIcorrect of
them correct), and the point-to-point and collective programs of \MBB
level~2~\citep{jammer24mbb} (\nMBBprogs). The baseline is \MUST~1.9.2, run in \MBB's
container with the same timeout. \pending{Stress-testing baseline: $N$ runs per program
with random delays injected by the replay library. PARCOACH if it builds from the
\MBB container.}

\subsection{RQ6: real applications}

\paragraph{A production bug from one clean run.} HYPRE~2.10.1's ParaSails preconditioner
exchanges matrix rows twice, first the pruned rows and then the stored rows. Both exchanges
send their requests with tag~222 and take them with \mpicall{Probe(ANY\_SOURCE, 222)}
followed by a receive from the probed source. A rank that has finished the first exchange can
send its stored-rows request while a neighbour is still probing for pruned-rows requests. The
probe then takes it, and the run hangs. In production this hang appeared intermittently for 18
months, and diagnosing it took 291 jobs and 10\,392 compute-node hours~\citep{sato17ninja}.
Version~2.11.0 fixed it by giving the two exchanges different tags.

We traced one run of HYPRE's \texttt{ij} driver with ParaSails-PCG on four processes. The run
finished normally after 19 iterations. Among \tool's 25 probe alternatives, one says that rank~2's
second pruned-rows probe could have reported rank~3's 800-byte request, the stored-rows
request of the next exchange, instead of rank~1's 400-byte pruned-rows request, for every
threshold of at least 3\,444 bytes. The other request-exchange alternatives have the same
shape: the other neighbour's pruned-rows request. Replayed with a probe pin, the predicted
alternative hangs. Its control, which pins the same probe to the sender it saw, finishes with
the recorded residual, and so do the same-shape alternatives and their controls. On
version~2.11.0 the alternative does not exist (\cref{tab:hypre}). A second trace of the same
configuration recorded the neighbours in another order and showed the alternative at two
probes. Both hung when replayed, and both controls finished. Which probe exposes the race
depends on the order recorded, which is the point of prediction: the run itself showed nothing.

\tool reports the race as a probe alternative, a warning, with the remark that a count taken
from the probe would differ. It does not report a deadlock: the hang happens after the probe,
and the receive that follows takes its source from the probe's status, so the continuation is
beyond the horizon. The replay supplies what the trace cannot. Grouped by call site, the 25
probe alternatives of a trace fall at four sites: HYPRE's own \mpicall{Iprobe} wrapper in its
data exchange, the diagonal-scaling exchange, ParaSails's \texttt{ReceiveReplyPrunedRows},
and its \texttt{ReceiveRequest}, the probe for tag~222 where the race lies. \pending{Site counts over
the campaign's traces, from the site column of the rerun.}

\subsection{Threats to validity}

\pending{One node and few ranks; the corpora's programs are small; twins are written
knowing the labels; \MUST runs a different build of each program under MPICH, so it sees
a different run; the model's premises (complete trace of the modelled fragment, a single
threshold per implementation, angelic \mpicall{Waitany}).}
