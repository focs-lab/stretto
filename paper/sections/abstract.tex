A receive in an MPI program may name no sender and take whichever matching message
arrives first. Which message that is depends on timing, so one program on one input can
deadlock, lose a message or compute different numbers in one run out of many, and the
failure is gone when the run is repeated. Runtime checkers judge only the run that
happened. Exhaustive verifiers enumerate schedules and pay for every competing wildcard.
Predictive analyses of one MPI trace either keep every wildcard match fixed, or search other
matchings with a solver, under assumptions on how a program's calls depend on what it
receives.

We carry sound predictive analysis from shared-memory concurrency to \emph{alternative}
matchings, in which a wildcard receive, probe or \texttt{Waitany} takes a different message.
From one trace, our tool \tool enumerates them, decides each one with a graph check over the
part of the trace the change cannot affect, profiles it over the buffering threshold of the
MPI implementation, and emits a pin that forces it in a replay. We prove that an accepted
alternative is realisable by every program consistent with the trace up to that part, and
that the check is complete relative to it. The check covers MPI's matching semantics and
needs no solver; per alternative, it takes time quasi-linear in the trace for bounded ranks
and tags. Above the threshold the observed run needs, feasibility of a steal at a blocking
receive is monotone in the threshold, while deadlock predictions, as known for programs with
wildcards, are not. After the changed receive, the recorded calls provably still hold until
the program first reads the changed result, which a static analysis bounds; beyond that,
consequences are explored under the single-path assumption, which we show can be false when a
destination comes from a message's status.
From single clean runs of HYPRE~2.10.1, \tool reports the message race in its ParaSails
preconditioner that took 10\,392 compute-node hours to diagnose, as a probe alternative in
\nHypreExposed of \nHypreTraced traced runs. Replayed at the probe whose tag the documented fix
changed, all \nHypreCrossAlts such alternatives hang while their controls finish. Random
delays hung it in none of \nHypreStressRuns runs and NINJA, a noise injector built for this race,
in at most \nNinjaHypreEightAppHangSetup of \nNinjaHypreEightAppRuns; the fixed version
has no such alternative. \tool also predicts the documented wildcard bugs of NPB MG~2.4.1 and deal.II~9.3.0-rc1. On \nMBIprogs
programs of the MPI Bugs Initiative about matching, it finds \nMBItpunion of \nMBIerrors
labelled errors with no false error report: \nMBItpobserved shown by the traced run,
\nMBItpPredBuf buffering thresholds and \nMBItpPredSP single-path consequences (F1
\MBIfoneunion, against \MBIfoneMUST for \MUST and \MBIfonestress for randomised runs).
