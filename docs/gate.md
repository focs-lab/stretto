# Project gate (benchmark level)

First written 2026-09-07, superseding the idiom-level `wp0-gate.md`; rewritten 2026-10-16
from the single corpus run that followed the audit (`experiments/RUNBOOK.md`). The three
criteria of proposal §15 are measured on benchmark programs (MBI, MPI-BugBench level 2) and
a real application (AMG), with MUST 1.9.2 as the observational baseline and pinned replay
as the confirmation. MUST builds the same source with MPICH in its own container and runs it
once with the same timeout, so its verdicts come from a different run of the same program.
Every number below names the table of `docs/results.md` it comes from (generated by
`experiments/tables.py` from the CSV files under `experiments/results/`); the per-program
evidence is in `experiments/results/<corpus>/<program>/` (trace, report, run and replay
logs), which is not committed.

Two kinds of findings are kept apart throughout. *Observed* findings are what the run itself
showed (a blocked or spinning rank, a collective mismatch, a message never received);
any observational tool sees them. *Predicted* findings are claims about other runs: a
mismatch certain from the trace (1a), a deadlock or orphan certified under the single-path
assumption (1c, 1d), a finished run that deadlocks below a buffering threshold
(2-buffering). The classes 1b, 1f, probe-alt and waitany-order are warnings and never count
as errors. The results tables show the observed floor, the predicted part and their union.

## Criterion 1: ≥ 3 benchmark bugs predicted from a run in which MUST reports nothing, confirmed by replay

**Met.** MBI, 115 programs (results table "MPI Bugs Initiative", column `detail`): 34
`MessageRace`, 15 `TagMatching`, 12 `BufferingHazard`, 4 `CallMatching` (the probe
programs) and 50 correct.

- Rematch, union: TP 61, FP 0, FN 4, TN 50 (precision 1.00, recall 0.94, F1 0.97).
  The observed floor alone is TP 39 (F1 0.75); the predicted part alone TP 51 (F1 0.88).
  MUST 1.9.2 (`--must:distributed`): TP 46, FP 0, FN 19 (F1 0.83); MUST verdicts ERROR 46,
  OK 63, RE 2, TIMEOUT 4.
- Labelled errors Rematch reports and MUST does not on the same program: 15. Of these, 7
  are predicted on a run that showed nothing itself (the run finished): the `Gather`,
  `Reduce` (×2) and `Loop` (×4) message-race programs, where the racing receive is flagged at
  L1 and a deadlock and an orphan are certified under the single-path assumption. All 7 are
  replay-confirmed. The other 8 are observed hangs (four probe `CallOrdering` programs, four
  collective message-race programs) on which MUST times out or reports nothing.
- Replays (results table "Replays, one per error finding"): 1c 38/38 confirmed, 1d 25/25
  confirmed, 1b 2 informational. A replay confirms a finding only if the rerun reported every
  pin applied and reached the predicted outcome (a hang for 1c/1d). Findings with certainty
  `some` (the explorer found a deadlock in some, not every, continuation) are replayed with
  the pins of the explorer's witness execution, which is why the four `Loop` programs, whose
  first-pair pins did not reproduce in the previous run, now confirm.

Message-race programs (results table "Message-race programs"): 34; 12 with a clean observed
run; the racing receive flagged at L1 in 33 (12/12 of the clean ones); a consequence
certified at L1+SP in 10 (10/12 clean), all 10 replay-confirmed; 22 deadlock or abort in
the observed run itself.

The four programs Rematch misses are `MessageRace_{Recv,Irecv}_{Send,Isend}_nok`, whose
outcome depends on a received value: the payload is the sender's rank and the program calls
`abort()` unless `buf1 != 3` is false (4 of the 34 race programs use this guard). At L1
they get the racing-receive warning only. E7 (results table "E7") analyses them with a
hand-written L2 twin that writes the check as a branch on the message's source: the twin
yields class 1e (the program aborts on its own check) in all four. Twins are not part of
the scored verdict, so they stay FN in the table above.

## Criterion 2: ≥ 1 of those is family ① (message race), not family ③

**Met.** The seven clean-run predictions above are family ①: classes 1f (racing receive),
1c (orphan) and 1d (deadlock), each with the wildcard receive and the message that cause it.
`MessageRace_tag_ANY_TAG_1_Send_Recv_nok` is 1b (cross-purpose tag) with an observed hang
and an informational replay. Idiom 05 (1a, count mismatch) reproduces as `MPI_ERR_TRUNCATE`
on both Open MPI and MPICH (`scripts/replay_idiom.sh`).

## Criterion 3: ≥ 1 requires going beyond single-path

**Met, in the strong form** (results table "E3", idioms). Idiom 01 (master–worker,
destination = `MPI_SOURCE`): the single-path level predicts a deadlock at B = 0 that the
program cannot reach; the L2 twin gives `done`. Idiom 06 (collective participation depends on
`MPI_SOURCE`): single-path finds a deadlock for the wrong reason; the twin gives the real one.
MBI's own payload-dependent races (above) are certifiable only with the value skeleton, and
E7 does so with twins. Theorem T5 of `model.md` states the lemma; E3 and E7 are its evidence.

## Second corpus: MPI-BugBench level 2

396 programs (results table "MPI-BugBench level 2"): every point-to-point and collective
call-ordering, missing-call and local-concurrency program and every correct one. Eight use
MPI-4 partitioned communication, which Open MPI 4.1.6 does not provide, and are left out.
On the other 388:

| | TP | FP | FN | TN | F1 |
|---|---|---|---|---|---|
| Rematch (union) | 216 | 4 | 20 | 148 | 0.95 |
| Rematch, observed in the run | 216 | 4 | 20 | 148 | 0.95 |
| Rematch, predicted | 9 | 0 | 227 | 152 | 0.07 |
| MUST 1.9.2 | 213 | 4 | 23 | 148 | 0.94 |

- **The corpus is observational.** The predicted row is almost empty because the bugs show
  in the run itself: collective mismatches, blocked ranks, ranks spinning in an `Improbe`
  loop, unreceived sends. Two labelled-error programs use a wildcard; one hangs in the
  observed run with the alternative flagged at L1, the other has a single sender whose FIFO
  order leaves no alternative and shows as an unreceived send. MPI-BugBench measures the
  observational floor and the false-positive rate on correct programs; MBI is where
  prediction shows.
- **Rematch's four false positives are label disagreements** (column `run` =
  `MPI-ERROR:MPI_ERR_ARG`): correct-labelled `MPI_Gather`/`MPI_Reduce` programs that pass
  `MPI_IN_PLACE` on non-root ranks. Open MPI aborts the run; Rematch reports the aborted run
  (2-blocked). MUST's run of the same four crashes (RE).
- **Rematch's 20 false negatives are all local-concurrency programs** (column `detail`): a
  buffer reused before its nonblocking operation completes. That is family ③; PMPI
  interposition does not see memory accesses.
- **Six labelled errors only Rematch reports:** probe-driven hangs and unmatched
  `Improbe`/`Mprobe` calls, reported from the observed run (a blocked rank, a rank spinning
  in a polling loop, a send never received); MUST times out on five and crashes on one.
- **Three errors only MUST reports:** two receives into overlapping buffers (its buffer
  checks, family ③) and the local-concurrency `Imrecv` program, which MUST reports as a
  deadlock, as it does for the four correct `Mprobe`/`Improbe`/`Mrecv`/`Imrecv` programs
  that are its false positives.
- Warnings on correct programs: none (MBI: 29 of 50 correct programs carry a 1f or 1b
  warning, results line "Correct programs"); wildcard competition on MBI: 165 wildcard
  receives, 144 feasible L1 alternatives, 0.87 per wildcard receive, at most 7 in one program
  (results line "Wildcard competition").

## Checker against explorer (E6)

Results table "E6". The checker in L1 mode, the claim the report makes, against exhaustive
exploration of the trace as a straight-line program, at B = 0 and B = ∞, on every corpus and
idiom trace with at most 2000 events and on 200 random programs whose explorer-chosen
execution is the trace (`dsl.random_matched_program`, `dsl.trace_from_execution`):

| traces | pairs (alternative, B) | agree | unsound | incomplete | exact as well | events, max |
|---|---|---|---|---|---|---|
| corpus and idiom traces (71) | 306 | 306 | 0 | 0 | 118 | 48 |
| synthetic traces (127) | 528 | 525 | 0 | 3 | 96 | 72 |

*Unsound* would be an accepted alternative that no execution realises on the receives inside
the checker's cut; there is none. The run on the second machine had one, on a synthetic
trace: a pending `Irecv` from ANY/ANY followed by a specific receive whose message the
`Irecv` accepts. It became horizon rule 6 (`model.md` §3, the standard's second
non-overtaking clause), after which the corpus tables are unchanged and the pair is
rejected. The three *incomplete* pairs are rejections where the explorer realises the pair
only by re-matching a second wildcard receive outside the judged set: a two-change
alternative, which the single-change claim does not cover (T2 is stated for single changes).
The checker is two to three orders of magnitude faster on these small traces
(columns "checker time", "explorer time"); the explorer's cost grows exponentially.

## Buffering (E2)

Results table "E2". Every alternative and every observed run is checked at every
breakpoint (0, each message size, ∞), not bisected: over 516 traces, no profile is
non-monotone in B (theorem T2's evidence). 51 observed runs are infeasible at B = 0: they
deadlock on a rendezvous implementation (2-buffering). Of 153 feasible alternatives, 140 are
feasible at B = 0 and all 153 from B = 4096 on; the 13 B-dependent ones are steals in MBI's
loop message-race programs that need the stolen message buffered (B ≥ 4). The eager size of
the implementation is measured, not assumed (`b_impl.csv`): Open MPI 4.1.6 buffers up to
4040 bytes by default and no less than 256 bytes when forced down. Replaying the 19 programs
whose finished run is realisable only above a threshold: 19/19 finish again with the default
limits, as predicted; their bounds (4 and 40 bytes) lie below the smallest eager size the
transport accepts, so the forced-rendezvous replay cannot test them on this implementation,
and the table says "untestable" rather than claiming a confirmation.

## Scale (E4, E5)

Results table "E4" (NPB 3.4.3, MPICH build), from one timed leg on the second machine with
the whole host idle (`experiments/timing_leg.sh`, `experiments/results/timing-leg.log`). The
traced run takes between 0.99 and 1.07 times the plain one (most runs last about 4.5 s,
mostly launcher start-up; the 1.07 is lu.A at 16 ranks, whose 380 MB trace is written
during the run). Analysis, one process: lu.A at 16 ranks, 3 049 812 events, 50.0 s (49.3 s in
the leg's second pass); lu.A at 4 ranks, 508 376 events, 7.9 s; cg.A at 16 ranks, 235 680
events, 3.5 s. That is about 16 µs per event on traces without wildcard receives, where the
cost is loading and the observed-run checks.

Results section "E5" (AMG, 8 ranks, `summary8.txt`): 39 643 sends, 53 wildcard receives,
10 978 probes. The analysis reports 5 racing receives (1f) and 3263 probe alternatives, all
at L1, in 13.2 s with a peak of 0.55 GB in the same timed leg (13.0 s in its second pass;
9.3 s on the development host). The 3263 probe alternatives are profiled at the two ends of
the B range and bisected between them (exact by T2); judging all of the about 260
breakpoints (`--full-profile`) gives the same findings in 300 s and 1.2 GB on the development
host. A pinned replay of the first probe alternative
(`confirm8.txt`) reports the pin applied and runs to completion with the other sender, so the
alternative is realisable and, as the metadata-driven continuation predicts, benign. MUST
1.9.2 on the same build (`must8-*/verdict.txt`): the distributed layout, used on the corpora,
crashes inside its wait-state module (RE); the centralised layout completes and reports
requests not freed at `MPI_Finalize` on every rank plus 103 warnings about zero counts and
null requests, and nothing about message matching. No harmful alternative was found in AMG,
which is the false-positive evidence on wildcard-heavy correct code the gate asked for; the
proposal's §19 minimum is restated accordingly (a prediction on a real application confirmed
realisable by replay, and benchmark bugs MUST misses confirmed).

## WP0a (payload-obliviousness) on the full corpus

`study/sites.csv`: 19 wildcard/probe/Waitany sites in AMG, MACSio and Nekbone, 18
metadata-only or none. MBI: 80 wildcard programs, all with metadata-only continuations except
the `buf1 != 3` guard, whose payload mirrors the sender's rank (4 programs). MPI-BugBench
level 2: 2 wildcard call-ordering programs (same shape) and 13 tag-parameter programs. AMG at
8 ranks: the `Iprobe(MPI_ANY_SOURCE)` loops in `exchange_data.c` produce probe alternatives
whose continuation (the following `Recv(status.MPI_SOURCE)`) is metadata-driven. The bet
holds on everything measured; the two patterns to add to the model are probe-driven loops
and payload-mirrors-metadata, the second now covered by twins (E7).

## Related-work verdict

The horizon is prior art (MAD, 2000; *Detecting Unaffected Race Conditions in Message-Passing
Programs*, 2004); the complexity landscape for channels is *The Complexity of Testing
Message-Passing Concurrency* (POPL'26). What is new and demonstrated here: the feasibility
criterion with a per-alternative linear check for MPI-shaped channels (T4), the consequence
taxonomy with the observed/predicted split, the buffering profile with replay-backed
intervals and a measured eager size, the L1 / L1+SP / L2 split with evidence that
single-path is unsound on metadata-dependent code (T5, E3, E7), the checker-versus-explorer
differential (E6), and a tool with 0 false positives on MBI and 4 label disagreements on
MPI-BugBench. See `related-work/analysis.md` and `proposal-delta.md`.

## Decision

**Continue on the PLDI/OOPSLA trajectory** with proposal v4 (`proposal_EN.md`). Open risks:
the two-change rung (E6 shows where single-change stops), the value skeleton beyond
hand-written twins, family ③ instrumentation, and the absence of a wildcard-heavy correct
real application besides AMG as false-positive evidence.
